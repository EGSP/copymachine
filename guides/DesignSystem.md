# Дизайн-система

## Концепция

- Интерфейс строгий, индустриальный и функциональный.
- Продукт должен ощущаться точным, надежным и контролируемым.

- Без закруглений в основных поверхностях и контролах интерфейса.

- Интерфейс компактный.

- Каждый интерактивный элемент должен давать понятную визуальную обратную связь.
- Состояния должны быть единообразными во всем продукте.
- Анимация должна быть короткой и функциональной, не декоративной.

---

## Правила для агента (машино-ориентированные)

### MUST (обязательно)

- Использовать компоненты `shadcn` в первую очередь, если подходящий компонент существует.
- Использовать utility-классы `Tailwind` как основной способ стилизации.
- Предпочитать шкалу отступов/размеров `Tailwind` (на базе `rem`) и значения `rem` вместо `px`.
- Использовать семантические токены для цветов и границ (например: `bg-background`, `text-foreground`, `border-border`, `ring-ring`).
- Сохранять прямые углы через `rounded-none`, если в этом документе не задано явное исключение.
- Определять и сохранять состояния интерактивных элементов там, где это применимо: `default`, `hover`, `active`, `focus-visible`, `disabled`, `error`.
- Сохранять интерфейс компактным: группировать связанные элементы и избегать лишнего пустого пространства.
- Предпочитать композицию и встроенные API `variant`/`size` вместо точечных визуальных переопределений.

### SHOULD (рекомендуется)

- Использовать `gap-*` для ритма макета и консистентных расстояний между сгруппированными элементами.
- Делать переходы короткими и функциональными.
- Поддерживать высокую информационную плотность без ухудшения читаемости.
- Переиспользовать устоявшиеся паттерны для форм, навигации, таблиц и оверлеев.

### NEVER (запрещено)

- Не использовать декоративные градиенты, blur, glow или glass-эффекты.
- Не полагаться на raw-цветовые utility-классы, если доступны семантические токены.
- Не хардкодить пиксельные значения, когда тот же замысел выражается через шкалу `Tailwind` или `rem`.
- Не поставлять интерактивные элементы с неполными или несогласованными состояниями.

---

## Чеклист приемки UI

- Используются компоненты `shadcn`, где это возможно.
- Используются utility-классы `Tailwind` и семантические токены.
- Используются прямые углы (`rounded-none`) без случайных закруглений.
- Используются `rem`/шкала Tailwind вместо произвольных `px`.
- Присутствуют понятные интерактивные состояния (`hover`, `focus-visible`, `active`, `disabled`, `error` там, где нужно).
- Сохраняется компактный макет и понятная группировка.
- Сохраняется адаптивность при очевидной иерархии и ключевых действиях.
